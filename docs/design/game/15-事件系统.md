## 1. 系统概述

本模块重新设计**地图事件节点（❓）**的全部事件（原 `src/models/Events.ts` 的 8 种事件）。

- **范围**：只重设计「遭遇型事件」——玩家在地图事件节点触发的随机事件。
- **范围外**：「事件牌」「锦囊牌」两套系统已于 2026-09-02 取消（不再实现），本模块不包含也不依赖它们。
- 原 8 种事件（山神庙、拾荒、奇遇老者、赌坊、伏兵、流浪武士、宝箱、行脚商）全部并入新 20 事件，见 §6 末尾对照表。

## 2. 概率池规则

事件按稀有度分为 **4 个概率池**，抽取**先掷池、后掷事件**：

| 概率池 | 抽取概率 | 事件内容取向 | 数量 |
|:------:|:-------:|------|:----:|
| 旷古罕见 | **1%** | 传说级历史人物/典故（姜尚、项羽） | 2 |
| 凤毛麟角 | **5%** | 知名历史事件（赤壁、卧薪尝胆、高山流水、桃园） | 4 |
| 可遇难求 | **15%** | 精英级奇遇（隐士、老兵、古战场、赌马） | 5 |
| 稀松平常 | **79%** | 市井琐事（盗贼、强盗、算命先生、行脚商） | 9 |
| **合计** | **100%** | | **20** |

> **「越往上越可能出现历史事件」的落地方式**：概率池本身按稀有度分层——越高的池，事件越偏向历史人物/典故；同时历史类事件普遍带有**层数门槛**（第二章 10 层起、第三章 19 层起、第四章 28 层起逐步解锁），玩家越往上走，历史事件进入候选池的比例越高。

### 2.1 抽取逻辑

```
进入事件节点
  │
  ├─ 步骤一：掷概率池
  │    roll = rng() × 100
  │    roll < 1      → 旷古罕见
  │    roll < 6      → 凤毛麟角
  │    roll < 21     → 可遇难求
  │    否则          → 稀松平常
  │
  ├─ 步骤二：在该池内过滤「符合触发条件」的事件
  │    候选 = 池内事件中，满足全部条件者：
  │      · 出现层数包含当前层（含端点）
  │      · 触发条件全部成立（角色/资源/卜辞/队伍状态，见表 3.1）
  │      · 未被标记「本局已触发」（仅限可遇难求及以上，见 2.2）
  │
  ├─ 步骤三：从候选事件中随机取 1 个
  │
  └─ 兜底（候选为空时）：
       向更低一级概率池降级重抽（可遇难求 → 稀松平常）；
       稀松平常仍无候选 → 从全部 20 事件中无视条件随机 1 个；
       再失败（理论不可能）→ 该事件节点自动转为普通战斗节点。
```

> 关键点：**先定池、后定事件**。不会被低概率事件「占掉」高概率池名额，也不会因某个池内事件全被触发条件排除而浪费该池的概率。

### 2.2 每局唯一性

- **旷古罕见 / 凤毛麟角 / 可遇难求**：每局**至多触发一次**。触发后写入本局标记（`eventsTriggered`），后续抽取自动排除。防止反复刷 1% 大奖。
- **稀松平常**：可重复触发（市井琐事本就常见）。

### 2.3 触发条件与出现层数

| 触发条件类型 | 说明 | 示例 |
|------|------|------|
| 角色条件 | 是否拥有某名人杰 | 没有角色姜尚、拥有角色张飞或关羽 |
| 层数条件 | 当前层号 | 层数 ≥ 10 |
| 资源条件 | 通宝 / 天命数值门槛 | 通宝 ≥ 40、天命 ≤ 50 |
| 卜辞条件 | 卜辞栏持有状态 | 卜辞区有「乾为天」、卜辞栏张数 ≥ 1 |
| 队伍条件 | 阵容人数 | 队伍人数 < 10、队伍人数 ≥ 3 |

**出现层数**：事件可出现的层号区间（含端点，格式 `最小~最大`）。事件节点不会出现在 Boss 层（9/18/27/36 层），故新区间以各章非 Boss 层为主。

**不符合触发条件的事件不会触发**——不会先出现再判定失败。

## 3. 数据结构与效果类型

### 3.1 数据结构（扩展 `GameEvent`）

```ts
interface GameEvent {
  id: string;                    // 如 'jiyu_laozhe'
  title: string;                 // 事件名
  pool: 'legendary' | 'rare' | 'uncommon' | 'common';
                                 // 旷古罕见/凤毛麟角/可遇难求/稀松平常
  floors: [number, number];      // 出现层数，含端点，如 [1, 36]
  trigger: TriggerCondition[];   // 触发条件（AND），见 3.2
  oncePerRun: boolean;           // 每局唯一（可遇难求及以上 = true）
  description: string;           // 事件文本
  choices: EventChoice[];        // 选项
}
```

### 3.2 触发条件（判别联合）

```ts
type TriggerCondition =
  | { type: 'has_character'; characterId: PlayerCharacterId }        // 拥有某角色
  | { type: 'not_has_character'; characterId: PlayerCharacterId }    // 没有某角色
  | { type: 'floor_gte'; floor: number }                             // 层数 ≥ N（已由 floors 覆盖，保留作组合用）
  | { type: 'tongbao_gte'; amount: number }                          // 通宝 ≥ N
  | { type: 'destiny_lte'; amount: number }                          // 天命 ≤ N
  | { type: 'buci_has'; buciId: string }                             // 卜辞区有某卦
  | { type: 'buci_count_gte'; count: number }                        // 卜辞栏张数 ≥ N
  | { type: 'roster_count_gte'; count: number }                      // 队伍人数 ≥ N
  | { type: 'roster_count_lt'; count: number };                      // 队伍人数 < N
```

### 3.3 效果类型（扩展 `EventEffect`）

沿用已有：`none`、`tongbao`（±通宝）、`destiny`（±天命）、`buci`（随机卜辞）、`battle`（进入战斗）、`recruit`（打折招募）、`trade`（通宝换天命）、`gamble`（下注）。

新增：

| 效果 | 说明 | 数据 |
|------|------|------|
| `vitalityMaxUp` | **气数上限**永久 +N（跨战斗生效） | `{ amount: number }` |
| `recruitCharacter` | **直接获得**指定人杰（免通宝；队伍满时自动改为通宝补偿 50） | `{ characterId: PlayerCharacterId }` |
| `battleWithReward` | 进入战斗，胜利后额外 +N 通宝 | `{ reward: number }` |

### 3.4 依赖说明

- **气数上限持久化**：`RunState` 新增 `vitalityMaxBoost: number`（默认 0）。每场战斗初始气数上限 = `PLAYER_VITALITY(500) + vitalityMaxBoost`。

## 4. 抽取算法（实现参考）

```ts
/** 池边界（累计概率）：旷古罕见 <1，凤毛麟角 <6，可遇难求 <21，其余稀松平常 */
function rollEvent(run: RunState, rng: () => number): GameEvent {
  const roll = rng() * 100;
  const pools: Pool[] = roll < 1
    ? ['legendary', 'rare', 'uncommon', 'common']
    : roll < 6
      ? ['rare', 'uncommon', 'common']
      : roll < 21
        ? ['uncommon', 'common']
        : ['common'];

  for (const pool of pools) {
    const candidates = GAME_EVENTS.filter((e) =>
      e.pool === pool && floorInRange(run.floor, e.floors) &&
      triggersMet(run, e.trigger) && !(e.oncePerRun && run.eventsTriggered?.includes(e.id)),
    );
    if (candidates.length > 0) {
      return candidates[Math.floor(rng() * candidates.length)]!;
    }
  }
  // 兜底：无视条件随机（保证事件节点不空转）
  return GAME_EVENTS[Math.floor(rng() * GAME_EVENTS.length)]!;
}
```

> 降级链写死在池序列里（如抽中旷古罕见但无候选 → 依次尝试凤毛麟角→可遇难求→稀松平常），实现简单且与 §2.1 规则一致。
